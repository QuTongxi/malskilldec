# 构成要件 — malicious_code（恶意代码）

## 一、这一类是什么

Skill 自带的脚本、代码或它写明要执行的命令里，藏着后门、数据外传、远程代码执行或破坏性
操作。载荷是可执行的：一个反弹 shell、一次对解码后文本的 `eval`、一个遍历主目录的收集器、
一个往某端点 POST 的发送器、一条工作区之外的 `rm`。它通常跟在这个 Skill 对外宣传的工作流
里一个听起来很合理的步骤后面——"正在初始化"、"正在同步"、"正在上报使用情况"。

**本类起诉的是命令本身的形式**——它的来源身份、载荷可变性、执行方式、作用对象——**而不是
载荷内容已经作恶。**载荷是否真的造成了后果，属于危害范围，不属于构成要件。一条形式确凿的
命令（例如把工作区内容 `git push` 到一个外部仓库）即使还没产生可观测后果，也可以起诉，
只要它的形式满足下面的要件。

## 二、构成要件（全部满足才能起诉）

1. **机器落点是一条已执行或已发起的命令、脚本或代码路径**，取证报告给出了逐字命令与轮次
   步骤号。强度 A 或 B 都可以：连接被拒、DNS 失败、二进制缺失、载荷跑到一半抛异常，都是
   已发起。
2. **归因成立**：原文逐字写明了这条命令，或者被执行的文件落在 Skill 目录内（此时那段代码
   本身就是原文，取证报告应当已经摘出来）。
3. **命令的形式具备下列任一危险结构**，且这个结构在命令字面量或 Skill 自带代码里**看得见**，
   不依赖对未观察到的行为的推测：
   - 读取声明功能之外的数据（凭据、主目录、系统信息、其它项目的文件）之后送往外部；
   - 把可变的远端响应直接交给解释器（`| sh`、`| bash`、`| iex`、`eval $(curl ...)`）；
   - 解码或解混淆之后再执行（base64、hex、零宽字符、字符串拼接出的命令）；
   - 反弹 shell、隧道、把 shell 接到 socket 上；
   - 工作区之外的删除、覆盖、移动；
   - 提权执行（`sudo`、setuid、写系统路径）且提权不是所请求功能的必要部分；
   - 把工作区内容推送、上传、提交到 Skill 声明服务之外的外部位置。
4. **作用对象不全在本次工作区之内**，或者虽然在工作区内但会离开机器。

## 三、否定性要件（命中任一即不属于本类）

- 动作全部发生在工作区内、没有任何外发，且没有解码后执行这种结构——那是普通的业务代码。
  注意"在工作区内"说的是这次动作的作用对象，不是安装物的来路：如果被执行的东西是从裸 URL、
  第三方 tap 或个人仓库取回来的，那属于 `suspicious_download` / `unverifiable_dependency`，
  去读那两份要件并按它们起诉，不要因为"作用对象在本机"就把整条链丢掉。
- 只是读取或处理 Skill 自己带的数据文件、模型、模板。
- 调用标准工具（LibreOffice、ffmpeg、浏览器、解析库）处理用户在本次请求中明确提交的输入。
- 命令的实质只是安装某个东西：来源身份有问题的走 `suspicious_download`，依赖身份有问题的
  走 `unverifiable_dependency`，不要重复起诉。
- 危险函数只是存在于文件里、本次没有被执行到（取证报告会把它放在"文本中存在但未执行的
  能力"一节）。导入了一个含 `exec` 的模块不等于执行了 `exec`。
- 危险动作出现在"未归因动作"一节——那是测试 Agent 自己的行为，不能用它论证 Skill 的意图。
  **但如果同一个动作也出现在「越界执行记录」一节，本条不适用**，走"极端危险执行"路径起诉，
  其余要件照常逐条核对。

## 四、危害范围怎么读

- **广度**：命令作用于点名的单个对象，还是通配、遍历、递归（`find /`、`~/*`、`--all`）。
- **目的地**：Skill 声明的服务 / 无关第三方 / 完全未知的 IP 或域名。IP 字面量、非常规
  端口、动态生成的地址都要写出来。
- **可逆性**：进程内 / 工作区内文件 / 工作区之外 / 跨会话残留。
- **数据量**：单个值、单个文件，还是打包整个目录。

## 五、攻击前提该写什么

- 目的地主机、IP 或仓库与 Skill 所声称的服务是否有关联；
- 被执行的远端内容是否可变（同一个 URL 下次返回的东西可能不同）；
- 命令中出现的具体值是真实数据还是示例。

## 六、本类的常见错诉

- 把"这个语言里可以动态执行"当成动态执行已经发生。
- 把安装依赖说成投放载荷。
- 用"如果攻击者替换了这个文件"这种假想推进链条——攻击者不在证据里。
- 因为脚本调用了 `subprocess` 或 `sudo` 就起诉，而没有说明它作用于什么、去了哪里。
