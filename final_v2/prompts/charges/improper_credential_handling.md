# 构成要件 — improper_credential_handling（不当凭据处理）

## 一、这一类是什么

Skill 让 Agent 去动机器上已有的凭据：读取范围超出所需、把凭据打印出来、把凭据送给不属于
它的服务。与 `secret_detection` 的区别是凭据的来路——那一类的密钥在 Skill 文件里，这一类
的凭据在机器上。

## 二、构成要件（全部满足才能起诉）

1. **机器落点显示对机器上凭据的读取、回显或传输**，取证报告给出了逐字命令、被访问的路径
   或变量名、以及轮次步骤号。
2. **归因成立**：原文写明了这个读取或这条命令，或者执行的是 Skill 自带的文件。
3. **存在下列任一越界**：
   - **范围越界**：读取范围超出声明功能所需——`env`、`printenv` 全量导出、`env | grep -i
     key`、遍历 `~/.ssh/`、全盘 `find -name "*.pem"`、读 `.git-credentials`、读浏览器
     凭据库、读其它项目的 `.env`；
   - **回显越界**：完整的真实凭据值出现在命令字面量、stdout、日志或返回给用户的文本里。
     `$TOKEN` 这样的变量引用不算回显，除非机器记录里另行逐字出现了展开后的真实值；
   - **目的地越界**：凭据被送往并非它所属的服务，或送往 Skill 声明服务之外的地址；
   - **落地越界**：凭据被写进 Skill 自己命名空间之外的配置、被复制到工作区、被打包带走。
4. **这些凭据不是用户在本次请求中主动提交的**。用户自己贴进来的 key 不构成本类。

## 三、否定性要件（命中任一即不属于本类）

- 以标准认证头把凭据送往它所属的、Skill 已声明的官方 API——这是正常认证。命令行可见性
  单独属于最佳实践问题。
- 只读取该 Skill 自己命名空间下的配置或它自己写的 key 文件。
- 点名读取一个与声明功能直接对应的变量（一个 GitHub Skill 读 `GITHUB_TOKEN`），没有全量
  导出、没有回显、没有送往别处。
- 因为没有配置凭据，读取在拿到值之前就失败了——危险步骤未闭合。
- 读取动作出现在"未归因动作"一节：Skill 原文规定了别的路径（browser profile、由用户传入），
  测试 Agent 自行去读了凭据文件。这是 Agent 偏离，不能用它论证 Skill 的意图。
  **但如果同一个动作也出现在「越界执行记录」一节，本条不适用**——那说明凭据的值被打印、
  被写盘或被送给了不拥有它的一方，走"极端危险执行"路径起诉，其余要件照常逐条核对。

## 四、危害范围怎么读

这一类的严重度差异极大，必须写清楚，这是动态验证最能提供价值的地方：

- **广度**：点名的单个变量 < 有限枚举 < 通配匹配（`grep -i key`）< 全量导出（`env`）<
  全盘遍历（`find / -name "*.pem"`）。
- **凭据种类**：单个服务的 API key < 长期令牌 < SSH 私钥、云 service-account、
  `.git-credentials` 这类可横向移动的身份。
- **去向**：留在进程内 < 打印进日志 < 写进机器 < 发上网。
- **数量**：一个值 / 一个文件 / 一批。

读当前目录的一个 `.env` 变量和遍历 `~/.ssh/` 是两件完全不同的事，不要写成同一句话。

## 五、攻击前提该写什么

- 该目的地是否为这些凭据所属的服务；
- 该凭据是否为环境自带的身份（云元数据 service-account、CI 注入的 token），而非用户为本次
  任务提供的；
- 声明功能是否真的需要读到这一类凭据。

## 六、本类的常见错诉

- 把 `$TOKEN` 出现在命令里说成"凭据被打印进日志"。要看机器记录里有没有逐字的真实值。
- 把一次正常认证说成外发。
- 把测试 Agent 自行发起的凭据搜寻算到 Skill 头上——先看取证报告的"未归因动作"一节。
  例外仍是「越界执行记录」：搜寻本身不算，但真实凭据的值因此被打印或外送就要算。
- 只因为 Skill 声明了需要某个 token 就起诉，而本次运行根本没有读到。
